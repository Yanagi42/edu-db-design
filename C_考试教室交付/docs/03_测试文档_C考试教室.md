### 7.2 双会话资源竞争（待组内实际执行）

CALL sp_er_lock_term('2026-1');
UPDATE room_booking SET approval_status='已通过',reviewer='ADMIN_C',
  review_time=CURRENT_TIMESTAMP,review_comment='并发验证A'

## 8. 答辩要点与边界

1. 为什么名单不直接查行政班？跨班选修与退课必须以有效选课记录为准。
2. 为什么待审不占用、通过前还要再查？避免无效申请占用资源，也避免申请后资源变化造成审批冲突。
3. 为什么复用重叠函数？保证全组课程、考试、借用对周次、单双周、节次端点的判断一致。
4. 为什么有触发器还要事务和锁？触发器实施业务校验，事务保证整体回滚，统一锁处理并发的先查后写竞争。
5. 为什么缓考不删选课？缓考是考试资格状态，不改变修读关系；视图据审批状态动态改变应考状态。
6. 为什么审批人不是新建外键账号？避免依赖 A 的可选07权限模块；真实身份由公共身份层绑定，本模块保留审计标识。
7. 能否保证之后调课/选课永不冲突？本模块只能控制 C 的写入，其他成员的入口尚未采用相同锁；需在公共安排稳定后排考，公共数据变更后复核。
8. 座位是否固定？这里是按学号动态编排的逻辑座号，选退课或缓考变化后会重新编号；固定座位与多考场拆分不属于当前范围。
