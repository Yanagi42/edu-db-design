# 成员 C 手动测试指南

本指南在 A+C 的原始种子数据上按顺序操作，覆盖考试 6 项、教室 2 项。标记“预期报错”的语句请单独执行，查看报错后再手动执行下一条，避免图形客户端遇错停止整段脚本。

成功写入示例使用 `MAN_` 编号，每组执行一次即可。正式存储过程会自行提交，不要在外层加 `START TRANSACTION` 期望用 `ROLLBACK` 撤销。借用与缓考需保存审批历史，测试会留下这些记录，请使用自己的课设测试实例。

## 4. EX05：查询考试名单

```sql
SELECT student_id, student_name, attendance_status, deferral_status, seat_no
FROM v_er_exam_roster
WHERE exam_id='ERX001'
ORDER BY student_id;

SELECT COUNT(*) AS total,
       SUM(attendance_status='应考') AS normal_count,
       SUM(attendance_status='缓考') AS deferred_count,
       MAX(seat_no) AS max_seat
```

**预期：10人、9人应考、1人缓考、最大座号9。** S011 缓考无座位；S013 缓考被驳回，仍应考且有座位。

## 6. EX02：冲突与异常拦截

### 教室冲突

```sql
CALL sp_er_schedule_exam(
  'MAN_BAD_ROOM','O012','2026-1','R001','T018',17,1,1,2,50,0
);
```

**预期：ERROR 1644，消息含 `ER_ROOM_BUSY`**。该教室时段已经被 ERX001 占用。

### 监考教师冲突

```sql
CALL sp_er_schedule_exam(
  'MAN_BAD_TEACH','O012','2026-1','R014','T006',17,1,1,2,50,0
);
```

**预期：`ER_TEACHER_BUSY`**。教室不同，但 T006 正在监考 ERX001。

### 选课学生考试冲突

```sql
CALL sp_er_schedule_exam(
  'MAN_BAD_STU','O011','2026-1','R014','T018',17,2,3,4,30,0
);
```

**预期：`ER_STUDENT_BUSY`**。O011 与 O010 有共同选课学生，后者已在该时段安排 ERX004。虽然第5步已给 O011 安排了一场考试，本条会先命中学生冲突检查。

### 教室容量不足

```sql
CALL sp_er_schedule_exam(
  'MAN_BAD_CAP','O012','2026-1','R007','T018',18,6,5,6,40,1
);
```

**预期：`ER_ROOM_CAPACITY`**。R007 物理容量为30，不能分配40考位。

### 周次超出学期

```sql
CALL sp_er_schedule_exam(
  'MAN_BAD_WEEK','O012','2026-1','R014','T018',19,6,5,6,50,0
);
```

**预期：`ER_SLOT`**。当前学期总周数为18。

最后核对非法写入均无残留：

```sql
SELECT COUNT(*) AS failed_rows FROM exam WHERE exam_id LIKE 'MAN_BAD_%';
```

**预期：0。** 截图时保留错误消息和这条核查结果。

## 7. EX06：缓考申请与审批

S014 已选 O008，具有 ERX002 的申请资格，且没有种子缓考申请。

```sql
CALL sp_er_apply_deferral('MAN_DF01','ERX002','S014','因病申请缓考');

SELECT deferral_id, exam_id, approval_status, reviewer, review_time
FROM exam_deferral WHERE deferral_id='MAN_DF01';
```

**预期：待审核，审批人和审批时间为空。** 再审批：

```sql
CALL sp_er_review_deferral('MAN_DF01','已通过','ADMIN_C','证明齐全，同意缓考');

SELECT deferral_id, approval_status, reviewer, review_time, review_comment
FROM exam_deferral WHERE deferral_id='MAN_DF01';

SELECT student_id, attendance_status, seat_no
FROM v_er_exam_roster WHERE exam_id='ERX002' AND student_id='S014';
```

**预期：已通过，审批资料齐全；S014 名单状态变为缓考、座号 NULL。**

再次执行同一审批调用，预期 `ER_DEFERRAL_STATE`，原审批结果不变。

另可单独验证非本场学生申请：

```sql
CALL sp_er_apply_deferral('MAN_DF_BAD','ERX001','S001','测试无资格申请');
```

**预期：`ER_DEFERRAL_ENROLLMENT`**，没有产生 MAN_DF_BAD。最终缓考表为4条。

## 8. ROOM01、ROOM02：借用审批、空闲查询与取消释放

本组使用第18周日9–10节 R014，与前面的手动排考不同时间。

先查询：

```sql
CALL sp_er_free_rooms('2026-1',18,18,'全',7,9,10,40,1);
```

**预期：结果包含 R014。** 创建两个相同教室、时段的待审申请：

```sql
CALL sp_er_apply_booking(
  'MAN_BK01',NULL,'T006','2026-1','R014',18,18,'全',7,9,10,40,1,'教师交流'
);
CALL sp_er_apply_booking(
  'MAN_BK02','S011',NULL,'2026-1','R014',18,18,'全',7,9,10,40,1,'学生交流'
);

CALL sp_er_free_rooms('2026-1',18,18,'全',7,9,10,40,1);
```

**预期：两条申请均待审，查询仍包含 R014。** 申请人学生/教师二选一，另一个参数须为 NULL。

通过第一条，再查询：

```sql
CALL sp_er_review_booking('MAN_BK01','已通过','ADMIN_C','教室空闲，同意借用');
CALL sp_er_free_rooms('2026-1',18,18,'全',7,9,10,40,1);
```

**预期：查询不再包含 R014。** 尝试通过第二条（单独执行）：

```sql
CALL sp_er_review_booking('MAN_BK02','已通过','ADMIN_C','尝试同时间借用');
```

**预期：`ER_ROOM_BUSY`。** 核查第二条仍待审且无审批信息：

```sql
SELECT booking_id, approval_status, reviewer, review_time
FROM room_booking WHERE booking_id IN ('MAN_BK01','MAN_BK02');
```

取消第一条并核查释放：

```sql
CALL sp_er_cancel_booking('MAN_BK01','T006','活动改期');
CALL sp_er_free_rooms('2026-1',18,18,'全',7,9,10,40,1);

SELECT booking_id, approval_status, reviewer, review_time,
       cancelled_by, cancel_time, cancel_reason
FROM room_booking WHERE booking_id='MAN_BK01';
```

**预期：R014 重新出现；第一条已取消，但原审批和取消资料均保留。** 此时第二条可以通过：

```sql
CALL sp_er_review_booking('MAN_BK02','已通过','ADMIN_C','原借用取消，现可借用');
CALL sp_er_cancel_booking('MAN_BK02','S011','测试结束，释放教室');
```

最后一条取消用于释放测试时段，两条申请历史仍保留。

## 9. 可选：手动观察事务回滚

此组直接执行 SQL，故可以手动控制事务。开始后不要运行其他 DDL 或自行提交的业务过程。

```sql
START TRANSACTION;
CALL sp_er_lock_term('2026-1');

INSERT INTO exam(exam_id,offering_id,term_id,classroom_id,invigilator_id,
                 exam_week,day_of_week,start_section,end_section,seat_limit)
VALUES('MAN_TX01','O012','2026-1','R014','T018',18,7,5,6,50);

SELECT COUNT(*) FROM exam WHERE exam_id='MAN_TX01';
```

**预期：1。** 单独执行第二条有冲突的写入：

```sql
INSERT INTO exam(exam_id,offering_id,term_id,classroom_id,invigilator_id,
                 exam_week,day_of_week,start_section,end_section,seat_limit)
VALUES('MAN_TX02','O014','2026-1','R001','T018',17,1,1,2,60);
```

**预期：`ER_ROOM_BUSY`。** 此时第二条语句失败，第一条仍在当前事务中；接着主动回滚：

```sql
ROLLBACK;
SELECT COUNT(*) FROM exam WHERE exam_id IN ('MAN_TX01','MAN_TX02');
```

**预期：0。** 正式业务过程的异常处理器会自动执行这里的回滚；该手动示例展示回滚前后数据的区别。

双会话并发测试另见《03_测试文档》第7.2节，建议基本功能测试完成后再做。
