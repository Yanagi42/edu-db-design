# 教务系统系统设计：考试管理、教室管理（成员 C）

本稿对应阶段二，需求编号与阶段一一致。执行脚本为 `sql/04_exam_room_ddl.sql`，依赖 A 的 `01_base_ddl.sql`、`02_course_ddl.sql`。不依赖 B/D/E 或可选 `07_opt_rbac.sql`。

## 1. 功能结构与实现分工

| 需求 | 数据库实现 |
| :--- | :--- |
| EX01/EX02 安排、调整、冲突检查 | `exam`，两项考试事务过程，考试新增/修改触发器，共用资源与时间校验过程 |
| EX03 个人考表 | `v_er_student_exam`，按学号、学期过滤 |
| EX04 教师考表 | `v_er_teacher_exam`，合并任课及监考，保留角色标志 |
| EX05 考试名单 | `v_er_exam_roster`，有效选课、缓考标记和窗口函数座位编号 |
| EX06 缓考 | `exam_deferral`，申请/审批过程、状态与不可删除触发器 |
| ROOM01 借用审批 | `room_booking`，申请/审批/取消过程、资源复核及历史保护触发器 |
| ROOM02 空闲教室 | `v_er_room_occupancy`、`sp_er_free_rooms`，统一三种占用来源 |

结构校验使用主键、唯一约束、外键与 `CHECK`；跨行及跨表业务使用 C 自有表的触发器；并发串行化、提交与异常回滚使用事务存储过程。直接 DML 仍受到业务校验，但正式并发写入必须使用事务接口，不将直接 DML 作为有并发保证的接口。

## 2. 逻辑关系模式

下表 PK 为主键，UK 为候选唯一键，FK 为引用公共或本模块表的外键。C 的外键不配置级联修改/删除，避免公共主键变化绕开业务触发器及误删审批历史。

| 关系 | 主键、唯一键 | 外键与主要业务属性 |
| :--- | :--- | :--- |
| `exam` | PK `exam_id`；UK `offering_id` | FK `offering_id→course_offering`、`term_id→term`、`classroom_id→classroom`、`invigilator_id→teacher`；`exam_week, day_of_week, start_section, end_section, seat_limit, require_multimedia, created_at` |
| `room_booking` | PK `booking_id` | FK `applicant_student_id→student`、`applicant_teacher_id→teacher`、`term_id→term`、`classroom_id→classroom`；时间区间、人数、设备、用途、申请状态及申请/审批/取消留痕 |
| `exam_deferral` | PK `deferral_id`；UK `(exam_id,enrollment_id)` | FK `exam_id→exam`、`enrollment_id→enrollment`；`reason, approval_status, apply_time, reviewer, review_time, review_comment` |
| `er_term_lock` | PK/FK `term_id→term` | 仅用于锁定 C 模块同学期写入，不是业务实体，不进入概念 E-R 图 |

考试保留 `term_id` 便于按学期过滤和加锁，与 `offering_id` 所指学期的一致性由触发器检查。该受控冗余不复制课程名、教师名、学生名、实际人数或教室容量。

缓考只引用选课记录，不冗余保存学生与教学班，避免学生、选课、考试归属互相矛盾。教师多对多任课关系继续读取 A 的 `offering_teacher`。因此公共资料变更只维护公共表，查询即时关联。

## 3. 数据字典与约束

### 3.1 统一字段

| 字段 | 类型与约束 | 含义 |
| :--- | :--- | :--- |
| 业务编号和公共编号 | `VARCHAR(16)`，必填（两种申请人除外） | C 种子前缀 `ERX` 考试、`ERB` 借用、`ERD` 缓考；与 A 编号不冲突 |
| `exam_week` | `TINYINT UNSIGNED`，1–30 且不大于学期总周数 | 单次考试；调用重叠函数时传为起止周相等、全周 |
| `start_week/end_week` | `TINYINT UNSIGNED`，起止合法且不大于学期总周数 | 借用周区间 |
| `week_type` | `ENUM('全','单','双')` | 禁止只有一周却与奇偶性相反的空时间配置 |
| `day_of_week` | `TINYINT UNSIGNED`，1–7 | 星期一至日 |
| `start_section/end_section` | `TINYINT UNSIGNED`，1–12，结束不早于开始 | 闭区间；沿用 A 的 `fn_time_overlap` |
| `seat_limit/headcount` | `SMALLINT UNSIGNED`，1–500 | 考位/借用人数，不得超过物理教室容量 |
| `require_multimedia` | `TINYINT`，0/1 | 需要时要求教室 `is_multimedia=1` |
| 申请原因/用途/审批意见/取消原因 | `VARCHAR(255)` | 原因/用途必填且去空格后非空；终审意见与取消原因在相应状态必填 |
| 时间戳 | `DATETIME` | 申请/创建时间自动生成；审批/取消在执行操作时生成 |
| `reviewer/cancelled_by` | `VARCHAR(32)` | 来自 A 身份层的角色账号标识；相应操作时必填 |

### 3.2 考试约束

`offering_id` 唯一，限制每教学班一次正考。新建及改排均检查：教学班存在且未停开、学期一致；教室可用且满足考位与设备；实际有效选课人数不大于考位；监考教师在职；教室无三类占用；监考教师无监考或授课重叠；本班选课学生与其他考试或课程无重叠。改排时排除本场考试，不与自身冲突；考试编号、归属、创建时间不可修改。

容量按照全部有效选课人数保守校验，缓考通过不释放本场的容量预算。座位查询再排除通过缓考者。任课教师考表是信息查询关系；只有被明确安排监考的教师才占用本模块的监考资源，合讲教师不会因查询关系自动被安排监考。

### 3.3 借用与缓考状态约束

借用申请人字段二选一，既不能全空也不能都填。学生须在读、复学或留级，教师须在职。申请内容不可覆盖，要改时间或教室须取消后重新申请。

| 记录 | 允许的状态变化 | 强制留痕与检查 |
| :--- | :--- | :--- |
| 借用 | 待审→通过、驳回、取消；通过→取消 | 通过时重查资源与冲突；通过/驳回必须审批人、时间、意见；取消须操作者、时间、原因且保留原审批字段 |
| 缓考 | 待审→通过、驳回 | 申请/通过时核对本场有效选课；终审必须审批人、时间、意见 |

两类申请必须以待审状态插入，禁止直接插入已通过；禁止重复终审和状态回退，禁止物理删除审批历史。缓考重复申请由 `(exam_id,enrollment_id)` 唯一键拦截。对已经驳回的申请，本课设不提供重提/申诉流程。

## 4. 事务与流程设计

写入过程按“设置下一事务为 READ COMMITTED → 开始事务 → 获得学期资源锁 → 触发器校验并写入 → COMMIT”执行。异常处理统一 `ROLLBACK; RESIGNAL;`，客户端得到原始业务错误。所有 C 写入接口按照相同顺序获得学期锁，因此借用审批与考试安排能够串行检查同一批已提交资源，避免两个会话都先查到空闲后同时通过。

`er_term_lock` 使用 `INSERT ... ON DUPLICATE KEY UPDATE` 获得该学期行的 InnoDB 写锁。READ COMMITTED 让等待锁后的查询能看到前一事务刚提交的数据。按学期而不是按教室加锁，也覆盖“不同教室但同一监考或学生”的竞争。课设数据量较小，接受同学期写入串行化的吞吐代价。

事务过程是顶层入口，不能嵌入调用方已开始的事务，防止 `START TRANSACTION` 隐式提交调用方事务；批量事务示例直接执行受触发器保护的 SQL，并在进入业务写入前取得同样的锁。

无论空闲查询曾返回什么，审批都以事务内当前数据重新检查。缓考审批无需修改考试或选课原始数据，名单视图随状态即时变化，因此不会出现审批已通过但名单未同步的双写问题。

## 5. 过程接口与查询示例

接口参数顺序见 DDL 中过程声明；以下调用与种子一致，可直接用于演示。

```sql
-- 排考：编号、教学班、学期、教室、监考、周、星期、起止节、考位、多媒体。
CALL sp_er_schedule_exam('EX_DEMO','O011','2026-1','R007','T018',18,6,1,2,30,1);
-- 改排：编号、教室、监考、周、星期、起止节、考位、多媒体。
CALL sp_er_reschedule_exam('EX_DEMO','R014','T018',18,6,3,4,30,1);

-- 学生或教师申请人二选一；时间支持单双周。
CALL sp_er_apply_booking('BK_DEMO','S011',NULL,'2026-1','R014',18,18,'全',6,5,6,40,1,'学习交流');
CALL sp_er_review_booking('BK_DEMO','已通过','ADMIN_C','符合借用条件');
CALL sp_er_cancel_booking('BK_DEMO','S011','活动改期');

CALL sp_er_apply_deferral('DF_DEMO','ERX002','S014','因病申请');
CALL sp_er_review_deferral('DF_DEMO','已通过','ADMIN_C','证明齐全');
CALL sp_er_free_rooms('2026-1',17,17,'全',1,1,2,40,1);

SELECT * FROM v_er_student_exam WHERE student_id='S011' AND term_id='2026-1'
ORDER BY exam_week,day_of_week,start_section;
SELECT * FROM v_er_teacher_exam WHERE teacher_id='T002' AND term_id='2026-1'
ORDER BY exam_week,day_of_week,start_section;
SELECT * FROM v_er_exam_roster WHERE exam_id='ERX001' ORDER BY student_id;
```

以上写入示例用于独立演示，不能在验收脚本之前执行，以免改变固定测试基线。视图是查询契约，并不根据会话自动识别本人；正式授权由 A 绑定用户与角色，限制基表 DML 及内部校验过程的执行权限。

## 6. 物理设计与合稿边界

所有 C 表采用 InnoDB、`utf8mb4_0900_ai_ci`。考试索引按“学期+教室/监考+周+星期”收窄候选；借用索引按“学期+教室+审批状态+星期”收窄占用；申请人索引支持查询本人申请；缓考唯一键同时支持名单按考试、选课关联。先过滤学期、资源，再调用已有的重叠函数，避免仅凭函数全量扫描。

这里给出的是索引设计依据，不编造 `EXPLAIN` 耗时或加速倍数；全局优化实测由 A 负责。

本模块新增 4 表、4 视图、8 个触发器、15 个过程（7 个事务写入入口、1 个查询入口、7 个内部锁/校验过程）。编号统一以 `04_exam_room` 开头，内部对象统一 `er` 前缀，便于 E 汇总。

公共结构及其触发器保持不变。C 的同学期锁不能阻止 A/E 从其他入口修改选课、排课、教师或教室；跨模块并发与排考后的公共数据变化由集成阶段约定共同锁协议或暂停变更后重新校验。名单/座号为查询时动态结果，选退课或缓考改变后会重新编号，打印后应冻结业务数据；本课设不实现固定座位快照或自动分考场。
