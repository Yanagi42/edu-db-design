# A 模块接口审查与 B 成绩管理联调清单

审查基线：`main`，提交 `053fd11`。审查范围为仓库内 A 的 SQL、三阶段文档、分工清单，以及 B 的需求与设计草案。以下为静态审查结论；本机未启动 MySQL 8 服务，尚不能把 A 文档中的本地实测结果作为本机复验结果。

## 已确认的接口

| 业务对象 | 实际表与键 | B 模块使用方式 |
| :--- | :--- | :--- |
| 学生、教师 | `student.student_id`、`teacher.teacher_id`，均 `VARCHAR(16)` | 查询身份、录入教师外键 |

## 应请 A 修订或与全组统一的事项

1. **高：先修完成语义不等于及格。** `02_course_ddl.sql` 的 `sp_enroll_student`（约 823–847 行）把历史学期的 `enrollment.status='已选'` 且学期/教学班结束当成先修完成，即使 B 后续记录不及格也允许选后续课。A 的需求和设计文档称“先修课程满足/完成”，应明确是“修读过”还是“及格”；如要求及格，需在 B 成绩表落地后由 A 调整过程或通过最终集成迁移处理，并补充不及格与免修边界测试。B 不擅自改 `02_course_ddl.sql`。
2. **高：07 的视图尚未实现个人行隔离。** `07_opt_rbac.sql` 的 `v_teacher_my_courses`、`v_teacher_elective_roster`、`v_student_timetable`（约 185–268 行）返回全部教师或学生的行，仅输出 `teacher_id/student_id` 供调用方过滤。约 291–317 行的 MySQL 原生角色/GRANT 示例被整体注释；即便将 `GRANT SELECT` 启用，视图本身也不按当前用户过滤。现有测试只检查敏感字段是否出现在视图列中，不检验学生 A 能否读学生 B 的行。不能宣称“严格个人数据隔离”。需要账号与业务身份可信映射，并以两个不同的真实数据库账号做越权实测；B 的查分接口也必须做同样限制。
3. **中：排课授课资格的文档与过程不一致。** `01_需求分析_A组长.md` 的 `UC-KC-02` 要求先校验教师已关联教学班；`sp_assign_schedule`（`02_course_ddl.sql` 约 718–762 行）却先插排课，再 `INSERT IGNORE` 把未关联教师自动加入授课名单，`trg_course_schedule_bi` 未查授课关系。若希望排课时允许自动分配教师，应将需求写明；否则在写排课前拒绝未关联教师并增测。
4. **中：先修联系基数与 DDL 不一致。** `01_需求分析_A组长.md` 表 5-1 将课程—课程的先修写为 `M:N`，`course.prereq_course_id`（`02_course_ddl.sql` 约 15–40 行）每门课程最多只有一门直接先修，属于“一门后续课程至多关联一个前置课程”。若保留 DDL，应修正概念图和文字；如确需多门先修，则需要 A 独立建关联表并调整校验。老师强调避免重复和过度复杂，当前需求无多门先修例子时建议改文档。
5. **中：课程性质口径不一致。** `01_需求分析_A组长.md` 公共实体及 E-R 属性写 `必修/专业选修/公共选修/实践`，实际 `course.course_type` 只有 `必修/专业选修/公选`。统一用实际三值；若“实践”确为必需类别，须由 A 明确变更计划，B 暂不硬编码第四值。
6. **中：课程脚本重跑边界需写清。** `02_course_seed.sql` 多处直接插入排课、选课、调课记录；`02_course_test.sql` 还会新增 `S007 → O010` 等数据。不可假设在同一库无限重复运行造数与测试。全组应规定从空库按 `01_base_ddl → 01_base_seed → 02_course_ddl → 02_course_seed → 03_score_ddl → 03_score_seed → 03_score_test` 初始化，并在各模块测试前约定是否运行 `02_course_test`。`07_opt_rbac` 包含压测样本的生成与删除，集成时最后执行并确认不误删模块数据。

## B 模块的落地检查

- [ ] DDL 只新建 `03_score_*` 对象，不修改 01/02 表；外键字段类型与字符集匹配，`score.enrollment_id` 唯一且非空。

- [ ] 审批更新正式成绩与申请状态在同一事务；待审申请并发唯一性、重复审批、已发布成绩绕过审批的直接更新分别测试。

- [ ] 用 **MySQL 8** 从空库依次执行脚本并保存实际测试输出；当前本机 MariaDB 客户端不能替代 MySQL 8 验证。
