# 成绩管理模块系统设计（B）

> 成员 B；对应 `01_需求分析_B成绩管理.md`。已对照 A 仓库提交 `053fd11` 的 `01_base_ddl.sql`、`02_course_ddl.sql`，实现见 `../sql/03_score_ddl.sql`。2026-11-25 已在 MySQL 8.0.46 完成 B 脚本实测，详见 `03_测试与验证_B成绩管理.md`。

## 1 功能模块及核心流程

| 功能模块 | 输入与处理 | 设计关联 |
| :--- | :--- | :--- |
| 成绩登分 | 从有效选课关系生成教师登分册；教师保存草稿、整批提交；教务员审核发布 | 课程成绩（含初次审核字段）；引用学生、开课教学班、选课、授课关系 |
| 成绩更正 | 教师申请修改；教务员审批；通过时原成绩、申请结果和历史共同生效 | 成绩修改申请（含前后值和审批结论） |
| 查卷复核 | 学生申请；教师核查；教务员确认；需要改分时进入更正审批 | 成绩复核申请（含教师核查与教务确认结果） |
| 查询统计 | 按学生、学期、课程、教学班、教师、专业和年级查询，计算分布、排名、不及格及专业选修学分 | 仅按已发布数值成绩参加统计，特殊状态另列 |

**录入与发布**：校验任课身份、选课有效性和成绩范围 → 保存草稿 → 检查名单完整性 → 整批待审核 → 教务员通过并发布，或退回。批次提交及审核各自要求事务一致性。学生只能看到已发布值。

**修改与复核**：已发布成绩建立修改申请，保存原值和拟改值；审批通过时校验原值仍有效，在同一事务内更新正式成绩与申请的审批结果。复核经教师核查和教务员确认，若需改分，则关联上述修改流程。审批事务失败时原成绩和申请状态保持不变。

## 2 逻辑结构设计

概念阶段只保留课程成绩、成绩修改申请、成绩复核申请三个新增实体，公共学生、教师、课程和教学班不重复建模。实际 DDL 不重复保存学生和教学班外键，统一经 `enrollment_id` 取得。

| 关系 | 关键属性与约束 | 设计理由 |
| :--- | :--- | :--- |
| 课程成绩 Score | `score_id BIGINT UNSIGNED` PK；`enrollment_id BIGINT UNSIGNED` 唯一 FK → `enrollment.enrollment_id`；`recorded_by_teacher_id VARCHAR(16)` FK → `teacher.teacher_id`；`reviewed_by_admin_id VARCHAR(32)` 可空，暂存审核人工号；`score_value` 可空、`exam_status`、`score_status`、`submitted_at`、`review_decision`、`review_comment`、`reviewed_at`、`published_at`。数值为 0–100。 | 一次选课至多一条成绩；学生和开课教学班由选课记录唯一确定，避免重复外键产生矛盾。录入时确认 `enrollment.status='已选'`，审批时处理后续退课的并发变更。 |
| 成绩修改申请 `score_change_request` | `request_id` PK；`score_id` FK、`applicant_teacher_id VARCHAR(16)` FK → `teacher.teacher_id`；`reviewer VARCHAR(32)` 可空，暂存审核人工号；`old_value`、`new_value`、`reason`、`status`、`decision_comment`、申请与审批时间。生成列 `pending_score_id` 仅对待审核申请取 `score_id`，唯一索引限制同一成绩同时仅一条待审。 | 经批准的申请同时构成可追溯的成绩变更历史，避免另设存放同样前后值的历史表。 |
| 成绩复核申请 `score_recheck_request` | `recheck_id` PK；`score_id` FK、核查教师 FK、确认教务员工号、相关修改申请 FK（后三者可空）；`reason`、`status`、`teacher_opinion`、`teacher_checked_at`、`admin_opinion`、`admin_confirmed_at`、`conclusion`、`requested_at`、`closed_at`。生成列 `open_score_id` 限制同一成绩同时仅一条未办结复核。申请学生由成绩关联的选课记录取得。 | 记录一次复核的申请、核查与结论。当前设计约定一次复核至多关联一条修改申请；如驳回后仍需改分，重新发起复核。 |

**范式与冗余**：课程名称、学分、类别、学生专业和年级从公共表取得，不复制进成绩表。修改申请保存前后值是历史业务事实。复核申请的学生由所属成绩的选课记录确定，不另存 `student_id`。课程学分与类别若会变化，需与 A 协商适用历史版本。

## 3 物理结构与设计依据

- MySQL InnoDB、utf8mb4、`utf8mb4_0900_ai_ci`；分数 `DECIMAL(5,2)`，`CHECK` 限制 0–100；`exam_status='正常'` 必须有分数，缓考或缺考必须为 `NULL`。`trg_score_bi` 核验选课有效和任课教师，`trg_score_bu` 防止变更原选课及录入人。MySQL 8 实测已验证 101 分被 `CHECK` 拦截；其余约束边界仍需按测试计划补测。
- `score.enrollment_id` 唯一约束防重复；`score_status`、录入教师以及两张申请表的业务外键设索引。教学班名单查询通过 A 已有的 `enrollment.offering_id` 索引连接，不在成绩表复制教学班。
- 修改申请的 `pending_score_id` 与复核申请的 `open_score_id` 用生成列和唯一索引实现“同一成绩最多一个未结束申请”，历史申请仍可多条；还需在 MySQL 8 验证并发。
- 成绩修改审批以事务锁定正式成绩与待审申请，校验 `old_value` 和状态，然后更新正式成绩与申请。失败回滚，并防重复审批。初次提交、发布同样避免半批成功。
- 状态与特殊成绩类别使用固定可校验取值，禁止未知字符串；金额式浮点误差不适用于成绩统计，分数与平均分采用十进制数值。
- 存储过程按传入业务 ID 核验授课归属与学生归属；传入的 ID 本身并非可信登录身份。A 的 `07_opt_rbac` 尚未提供可用的个人数据库账号映射及行权限；正式对外开放前须由集成层绑定登录者与业务 ID，并禁止普通账号直接写业务表。仅靠本阶段过程不能宣称抗身份冒用。

## 4 与成员 A 的接口契约

已确认：`student.student_id`、`teacher.teacher_id`、`term.term_id`、`course.course_id`、`course_offering.offering_id` 均为 `VARCHAR(16)`；`enrollment.enrollment_id` 为 `BIGINT UNSIGNED`，且 `(student_id, offering_id)` 唯一；`offering_teacher` 的联合主键为 `(offering_id, teacher_id)`；有效选课状态为 `已选`，退课为 `已退`；`course.course_type` 仅有 `必修/专业选修/公选`，`credit DECIMAL(3,1)`；`student.is_graduating` 标记毕业年级，`student.grade` 为入学年份。`01_base` 没有教务员主表，`07_opt_rbac` 才有可选的 `sys_user`，因此 `03_score_ddl.sql` 不得提前外键引用后者；审批人工号沿用 A 的 `schedule_change.reviewer VARCHAR(32)` 约定，统一权限集成时再明确身份绑定。

**联调待处理**：A 的 `sp_enroll_student` 把历史已选且已结课当作先修完成，尚未检查成绩是否及格。B 不能修改 A 的过程；在全组联调前由 A 确认“完成”口径并修订或明确保留该规则。`07_opt_rbac` 的角色视图当前也不按登录者过滤行，B 的学生查分和教师登分必须通过身份绑定的过程/权限机制实施，不能只依赖视图列脱敏。

**交付顺序**：A 的 `01_base_ddl.sql` → `01_base_seed.sql` → `02_course_ddl.sql` → `02_course_seed.sql` → B 的 `03_score_ddl.sql` → `03_score_seed.sql` → `03_score_test.sql`。若先运行 `02_course_test.sql`，会新增 `S007` 对 `O010` 的有效选课，B 的造数随之变化。脚本按从空库执行一次设计；本次在 A 已导入、B 首张表为空的现场用恢复模式完成 B 实测，尚未对整包从空库一键重建复验。

## 5 联调待定口径

1. 当前脚本采用初次教务审核后发布、草稿/待审核/退回/已发布四状态；如全组另有口径需统一调整。
2. 不及格学分按“历史不及格累计”还是“至今未通过课程”统计；本稿采用后者并对同一课程去重。
3. 重修、缓考、缺考如何标识，以及何时授予专业选修学分；排名是否只计成绩齐全学生。
4. 开课教学班是否有多个教师可分别录入，原录入人之外的教师如何获得修改授权。
