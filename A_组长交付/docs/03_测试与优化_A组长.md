## 2. 自动测试数据注入方案

### 2.1 公共底座造数（`01_base_seed.sql`）

采用 `INSERT ... ON DUPLICATE KEY UPDATE` 幂等语句结合批处理存储过程 `sp_seed_base_students()` 自动构造基础主数据，并在过程结束时自动回写各行政班 `student_count`（执行完自动清理该临时过程）：

- **实测数据规模**：`term` 3 行（`2025-1`、`2025-2` 已结束，`2026-1` 进行中且 `is_current=1`）、`college` 4 行（`COL01`–`COL04`）、`major` 5 行（`MAJ01`–`MAJ05`）、`admin_class` 8 行（`CLS01`–`CLS08`，覆盖 2023/2024/2025 级）、`teacher` 18 行（`T001`–`T018`）、`classroom` 16 行（`R001`–`R016`）、`student` 80 行（`S001`–`S080`，每班 10 人）。
- **跨模块与边界覆盖**：`CLS01`/`CLS03`/`CLS05` 标记毕业年级 `is_graduating=1`；`S078` 为休学、`S079` 为留级，用于学籍状态校验；`teacher` 覆盖 4 学院、4 类职称与 `29–54` 岁年龄段；`classroom` 故意混入非多媒体教室（`R005`/`R006`/`R011`）、小容量 30 人教室（`R007`）及维修中教室（`R016`），以触发全维度排课拦截测试。

### 2.2 课程业务造数（`02_course_seed.sql`）

- **课程与教学班**：15 门课程（`C001`–`C015`，覆盖必修/专业选修/公选及先修链 `C001 → C002 → C003 → C007/C008`、`C002 → C004 → C006`、`C009 → C010`、`C011 → C012`）；18 个开课教学班（历史 `O001`–`O006` 支撑先修课核验，当前 `2026-1` 学期 `O007`–`O018` 中包含多教师合讲班 `O007`/`O009`/`O013`/`O014`、初始满员 3/3 测试班 `O011` 以及初始未排课班 `O012`）。
- **排课、选课与审批样本**：15 条初始无冲突排课（`schedule_id` `1` 到 `15`，均实时通过 `trg_course_schedule_bi` 校验）、122 条初始选课记录（含 51 条历史已结课、70 条本学期有效选课与 1 条 `S008` 退课记录）、5 条初始调/停课样本（覆盖 `COL01` 多名教师的已通过/待审核/已驳回状态）、3 条免修/免听二级审批样本。
- **反范式一致性实测核验**：`02_course_seed.sql` 末尾执行了 18 个教学班的 `enrolled_count` 与 `enrollment` 实际有效行数比对，全部 18 行 `is_consistent` 均为 `1`（如 `O007`/`O008`/`O009` 为 `10=10`、`O010` 为 `6=6`、`O011` 为 `3=3`、`O012` 为 `0=0`、`O016` 剔除 1 条退课记录后为 `5=5`）。

### 2.3 大样本压测造数与自动清理（`07_opt_rbac.sql`）

为使 `EXPLAIN` 与 `EXPLAIN ANALYZE` 反映真实数据量级下的索引差异，编写基于 MySQL 8 `WITH RECURSIVE` 递归 CTE 的 `sp_generate_benchmark_data()` 与 `sp_cleanup_benchmark_data()`，所有压测数据均隔离于 `BM-T01`–`BM-T20`、`BM_CLS`、`BS0001`–`BS2000`、`BO0001`–`BO0100`、`BSO001`–`BSO020` 命名空间内：

- **压测期实测总规模**：`enrollment` **50,123 行**（50,000 条压测 + 123 条业务）、`course_schedule` **12,016 行**（11,400 条历史调停状态 + 600 条无冲突正常排课 + 16 条业务）、`schedule_change` **30,006 行**（30,000 条压测 + 6 条业务）。
- **测后洁净库核验**：`sp_cleanup_benchmark_data()` 执行后，实测表行数精准恢复为 `student` 80、`course_offering` 18、`course_schedule` 16、`enrollment` 123、`schedule_change` 6，且永久保留 RBAC 表、6 个视图与 5 个复合索引。

**4 组实测 SQL 与执行计划演进解析**：

1. **Q1（教学班有效名单倒序分页）**：
   ```sql
   SELECT e.student_id, s.student_name, e.enroll_time
   FROM enrollment e JOIN student s ON s.student_id = e.student_id
   WHERE e.offering_id = 'BO0015' AND e.status = '已选'
   ORDER BY e.enroll_time DESC LIMIT 50;
   ```
   - 优化前先通过单列索引 `idx_enroll_offering` 回表扫满 500 行、过滤剩 400 行后再内存 `Sort` 取前 50 行；落地 `idx_enroll_off_status_time (offering_id, status, enroll_time DESC, student_id)` 后，驱动表直接做降序覆盖索引查找，读够 50 行即终止（`0.0837 ms`），再通过 `student` 主键 `eq_ref` 点查补全姓名，总耗时由 `1.12 ms` 降至 `0.238 ms`。
2. **Q2（全校时间窗口选课热度统计）**：
   ```sql
   SELECT offering_id, COUNT(*) AS active_cnt
   FROM enrollment
   WHERE status = '已选' AND enroll_time >= '2026-08-25 00:00:00'
   GROUP BY offering_id;
   ```
   - 优化前因缺乏以 `status` 与 `enroll_time` 为前缀的索引，优化器被迫沿 `idx_enroll_offering` 扫描全部 `50,123` 行并回表过滤；建立覆盖索引 `idx_enroll_status_time_off (status, enroll_time, offering_id)` 后，访问类型由 `index` 升级为 `range`，仅在二级索引叶节点上顺序读取命中窗口的 `6,068` 行完成分组计数，耗时由 `105 ms` 骤降至 `10.2 ms`。
3. **Q3（学期+教室正常课表有序查询）**：
   ```sql
   SELECT schedule_id, offering_id, teacher_id, start_week, end_week, day_of_week, start_section, end_section
   FROM course_schedule
   WHERE term_id = 'BM-T01' AND classroom_id = 'R001' AND schedule_status = '正常'
   ORDER BY day_of_week, start_section;
   ```
   - 优化前依赖两个独立单列索引触发 `index_merge`（分别扫描 587 行和 802 行按主键求交集得到 192 行），回表筛出 2 条正常排课后再执行 `filesort`；落地 `idx_sched_term_room_status_time` 后，一次 `ref` 查找直接定位精确 2 行且天然有序，消除交集计算与排序，耗时由 `1.49 ms` 锐减至 `0.0569 ms`（提速 **26.2 倍**）。同步落地的对称索引 `idx_sched_term_teacher_status_time` 为教师个人课表提供同等量级加速。
4. **Q4（学期已通过调停课按教师分组统计）**：
   ```sql
   SELECT applicant_teacher_id, COUNT(*) AS total_cnt, SUM(change_type = '调课') AS adjust_cnt
   FROM schedule_change
   WHERE term_id = 'BM-T01' AND approval_status = '已通过'
   GROUP BY applicant_teacher_id;
   ```
   - 优化前需按 `idx_sc_term` 回表扫描 1,500 行并在内存中构建 `<temporary>` 临时表分组；落地 `idx_sc_term_status_teacher_type` 后，索引同时满足前缀过滤、分组有序与列覆盖，查询退化为纯流式覆盖索引聚合（`Group aggregate`），彻底消除临时表与回表，耗时由 `12.4 ms` 降至 `0.825 ms`。

### 5.2 逻辑查询优化总结

除物理索引外，全套测试与视图查询综合运用了四项逻辑改写策略：
1. **禁止无脑 `SELECT *`，定向触发覆盖索引**：如 Q1/Q2/Q4 仅查询必要字段，使优化器直接走 `Using index` 免回表。
2. **CTE 预聚合消除多对多连接扇出**：如测试项 8 将多教师与多排课分支拆入独立 CTE 聚合后再与教学班主表左连接，既避免数值重复累加，又防止中间结果集膨胀。
3. **避免在索引列上使用函数或表达式**：时间窗口过滤坚持使用 `enroll_time >= '2026-08-25 00:00:00'`（而非 `DATE(enroll_time) >= ...`），师资年龄统计直接读取 `teacher.age` 而非对 `birth_date` 调用日期函数，保障 B+ 树范围剪枝生效。
4. **先索引收窄候选集，再执行区间重叠判定**：在排课与选课冲突检查中，先利用 `(term_id, classroom_id/teacher_id, schedule_status)` 将候选排课压降至个位数，再调用 `fn_time_overlap` 按“星期 → 节次区间 → 周次交集 → 单双周互斥 → 单周奇偶”顺序短路判定，避免大表全量函数扫描。

### 5.3 物理存储与统计信息维护

大样本写入或批量清理后及时执行 `ANALYZE TABLE enrollment, course_schedule, schedule_change` 更新 InnoDB 索引基数估算，防止优化器基于过期统计信息错选全表扫描；配合第 3 章的反范式 `enrolled_count` 与第 4 章规划的历史学期归档/主从读写分离架构，确保高并发选课与复杂统计互不阻塞。
